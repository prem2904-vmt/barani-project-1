● Clean. The fix:

  Root cause: [ngModel] on type="number" inputs does a bidirectional sync
  through NumberValueAccessor. When the child emits a change, the parent updates
   its state, the parent re-renders the child with a new [validation] object,
  the child's input setter resets the signal, and ngModel writes the value back 
  into the DOM — which can briefly clear the input mid-type, especially if an
  intermediate parse returns null (e.g., while you're still typing the number).
  On top of that, the Clear all validation button appeared as soon as any rule
  was set, reinforcing the impression that typing had "wiped" something.

  What was happening: every keystroke in an input fired (input) → patch → emit →

   the parent's { ...p, validation: v.validation } spread sometimes produced a
  new p reference before the signal had fully propagated to [value] bindings.
  That intermediate state re-seeded the input with stale/empty values when focus
   shifted.
